# C4 Model reference

## Overview

C4 is a software architecture visualization model created by Simon Brown. It has four levels:

1. **Context** — The system's relationships with external users and systems; the broadest view
2. **Container** — Runtime units within the system, such as web applications, API services, databases, and message queues
3. **Component** — Logical modules and divisions of responsibility within a single container
4. **Code** — The class-diagram level, usually generated by an IDE rather than drawn manually

Choose a level that matches the audience. Use Context/Container for architecture reviews and Component/Code for developers.

> **Note**: Mermaid's C4 syntax (`C4Context`, `C4Container`, and `C4Component`) is an experimental extension.
> Mainstream renderers such as GitHub, VS Code, and Mermaid Live Editor support it,
> but the `parse()` API in the `mermaid` npm package may not fully support this syntax.
> The following examples use standard C4 Mermaid syntax and should render correctly in supported renderers.

---

## Context diagram

A system context diagram shows the complete set of interactions between the system, its users, and external systems.

```mermaid
C4Context
    title E-commerce platform — System Context Diagram

    Person(customer, "Customer", "Browse products, place orders")
    Person(admin, "Administrator", "Management of goods and orders")

    System(ecommerce, "E-commerce platform", "Provision of online shopping services")

    System_Ext(payment, "Payment Gateway", "Processing payment transactions")
    System_Ext(logistics, "Logistics system", "Processing distribution and tracking")
    System_Ext(email, "Mail service", "Send notifications")

    Rel(customer, ecommerce, "Browse products, place orders", "HTTPS")
    Rel(admin, ecommerce, "Manage backstage", "HTTPS")
    Rel(ecommerce, payment, "Initiating payment", "HTTPS/API")
    Rel(ecommerce, logistics, "Create shipping order", "HTTPS/API")
    Rel(ecommerce, email, "Send notifications", "SMTP")
```

## Container diagram

A container diagram shows the runtime units within the system and the technologies they use.

```mermaid
C4Container
    title E-commerce platform  —  Container Diagram

    Person(customer, "Customer", "Browse products, place orders")

    System_Boundary(ecommerce, "E-commerce platform") {
        Container(web, "Web Frontend", "React", "Provide user interface")
        Container(api, "API Services", "Go", "Processing business logic and route")
        Container(worker, "Async worker", "Python", "Handles background tasks such as emails and reports")
        ContainerDb(db, "Main database", "PostgreSQL", "Storage of goods, orders, user data")
        ContainerDb(cache, "Cache", "Redis", "Session and hot-data cache")
        ContainerQueue(mq, "Message queue", "RabbitMQ", "Async task distribution")
    }

    System_Ext(payment, "Payment Gateway", "Third-party payments")

    Rel(customer, web, "Visits", "HTTPS")
    Rel(web, api, "Call", "HTTPS/JSON")
    Rel(api, db, "Read and write", "TCP/5432")
    Rel(api, cache, "Read and write", "TCP/6379")
    Rel(api, mq, "Send Message", "AMQP")
    Rel(mq, worker, "Consumer Message", "AMQP")
    Rel(api, payment, "Initiating payment", "HTTPS")
```

## Component diagram

A component diagram shows the logical modules and dependencies within a single container.

```mermaid
C4Component
    title API Services  —  Component Diagram

    Container_Boundary(api, "API Services") {
        Component(router, "Route Layer", "Go/Chi", "HTTP routing and middleware")
        Component(auth, "Authentication module", "Go", "JWT Issuance and verification")
        Component(order, "Order module", "Go", "Order creation, query, status management")
        Component(product, "Product module", "Go", "Product CRUD and search")
        Component(repo, "Data Access Layer", "Go/sqlc", "SQL queries and transaction management")
    }

    ContainerDb(db, "PostgreSQL", "Main database")
    ContainerDb(cache, "Redis", "Cache")
    System_Ext(payment, "Payment Gateway", "Third parties")

    Rel(router, auth, "Validate tokens")
    Rel(router, order, "Request for forwarding orders")
    Rel(router, product, "Forward product requests")
    Rel(order, repo, "Persist orders")
    Rel(order, payment, "Initiating payment", "HTTPS")
    Rel(product, repo, "Persist products")
    Rel(repo, db, "SQL queries", "TCP")
    Rel(auth, cache, "Reading and writing sessions", "TCP")
```
